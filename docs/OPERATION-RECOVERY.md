# 最近操作恢复

2026-10-16。目标是撤销 Agent 最近做错的文件操作。普通任务不再自动创建 Git 检查点，不遍历整个 vault，也不读取无关附件。

## 方案取舍

| 方案 | 成本与适用范围 | 本次选择 |
| --- | --- | --- |
| 每轮整库 Git 快照 | 扫描所有文件，维护长期版本，依赖 Git | 降为可选手动高级功能 |
| 每轮复制整个目录 / ZIP | 不依赖 Git，但仍扫描并复制无关文件 | 不采用 |
| 操作日志与原文备份 | 只保存工具实际修改的文件，按相反顺序撤销 | 默认机制 |

修改前持久化原文、结果、路径、轮次及状态。最近操作窗口显示最近 20 个有文件操作的轮次；用户先看清单和反向 diff，再确认撤销。全部操作记录保留单项撤销入口。

## 可恢复内容

- 修改：当前内容仍等于 Agent 写入结果时恢复原文。
- 新建：内容匹配才移入 `VaultBridge Recovery`，保留副本。
- 移动/重命名：当前内容匹配且原位置空闲时移回。
- 删除：原位置空闲时从操作记录恢复原文；删除时保留的副本仍留在恢复目录。
- 外部文本修改/新建：使用相同计划及校验流程，目录仍须在用户授权列表中。手动恢复不会重新开启 Agent 的外部写权限。
- 同一轮连续修改、移动、重命名、删除，以及新建后再编辑：通过虚拟路径状态倒序检查整轮操作。

笔记内容优先使用当前 Obsidian 编辑缓冲区。外部编辑器未保存内容、任意 DataviewJS 副作用和用户手动导出卡片不在此机制内。不会倒退聊天记录，也不恢复空目录结构或文件权限。

## 冲突、中断和保存失败

1. 预览与确认执行都重新检查全部涉及路径。已知冲突发生时尚未修改任何文件。
2. 逐项执行时再次比较当前内容；无法锁住外部编辑器，因此多文件恢复不是原子事务。
3. 每项撤销前先写入 `undoing`，完成后写入 `undone`。中断保留原文与状态，报告已完成项。
4. 重启后的 `pending`、`undoing`，以及含失败项的整轮操作，不自动重放；在全部记录中检查 diff、错误及恢复副本。不会仅凭内容相同就删除结果未确认的新文件。
5. 修改日志保存失败立即阻断后续 Agent 写入。任务收尾失败向调用者抛错，队列暂停；已尝试的任务不会因点击“继续队列”而重复执行，须检查后移除，需要重试时重新发送。
6. 插件恢复操作使用同一工作区预留状态及写入串行队列，阻止新任务与撤销重叠。

记录继续保存在插件 `data.json`，兼容旧的操作记录。归档为用户显式操作：保留最近 20 轮、至少 100 条及未确认轮次，不拆分轮次；完整旧记录存入 `journal-archive` 后才从活动数据移除。恢复副本不自动删除。删除插件数据也会失去操作日志。

## 验证与升级

当前 0.7.3 的完整 Windows 套件共 99 项测试，全部通过。操作恢复覆盖重启、组合文件操作、预览后冲突、并发修改、持久化失败与不确定记录保护。真实 OpenCode 集成使用独立样本和脚本模型。原生审阅与嵌套撤销入口的键盘流程已经验证；未在用户笔记上执行破坏性测试。详见 [测试报告](../TEST_REPORT.md)。

升级器仅备份并替换三个发布文件，保留原插件 ID、data.json 与 runtime。旧 Git 阅读功能作为可选手动功能保留。
